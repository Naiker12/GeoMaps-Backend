ARQUITECTURA IMPLEMENTADA - REPORTES IA PROFESIONALES CON TYPST
Fecha: 2026-05-11

Objetivo:
Dejar el sistema de reportes fuera del flujo HTML/PDF y basado en una arquitectura profesional:

Spatial Engine -> AI Interpretation -> Python Assets -> Typst Renderer -> PDF GIS profesional

Cambios aplicados en el backend:

1. Nuevo renderer Typst
   Archivo:
   app/services/export/typst_service.py

   Responsabilidad:
   - Recibe el JSON universal del reporte.
   - Genera un archivo .typ temporal.
   - Ejecuta Typst mediante CLI global si existe o mediante el paquete Python typst.
   - Produce PDF vectorial profesional.
   - No depende de React para el PDF final.

2. Nuevo generador de assets tecnicos
   Archivo:
   app/services/export/technical_assets_service.py

   Responsabilidad:
   - Genera graficas tecnicas con Python/Matplotlib.
   - Genera grafica de barras.
   - Genera grafica circular.
   - Genera mapa tecnico de referencia.
   - Genera un mapa tecnico propio desde datos del reporte.

3. Integracion en endpoint de reportes
   Archivo:
   app/api/v1/endpoints/report_router.py

   Flujo nuevo:
   - ReportEngine genera report_json.
   - TypstPDFService genera el PDF profesional.
   - Si Typst no esta instalado o falla, el reporte falla de forma visible.
   - Guarda renderer = typst en Redis.

4. Contrato de status extendido
   Archivo:
   app/schemas/report_schemas.py

   Nuevo campo:
   renderer

   Sirve para confirmar que el PDF final fue generado por Typst.

5. Dependencia nueva
   Archivo:
   requirements.txt

   Agregados:
   matplotlib>=3.8.0
   typst==0.14.8

Estado actual:
- El backend ya esta preparado para usar Typst como motor principal.
- En esta maquina el comando typst global no esta instalado, pero el paquete Python typst si esta instalado en el venv.
- El renderer ya puede compilar PDF usando la API Python de Typst.

Pendiente para activar PDF profesional real:
1. En servidor, instalar dependencias con:
   venv/Scripts/python -m pip install -r requirements.txt
2. Ejecutar generacion de reporte.
3. Confirmar en /api/v1/reports/status/{report_id}:
   renderer = typst

Siguiente mejora recomendada:
- Mejorar el mapa tecnico para usar geometria real desde PostGIS:
  layer_features -> GeoJSON -> GeoPandas -> Matplotlib/Contextily -> PNG alta resolucion

- Agregar Rasterio para DEM, pendiente, escorrentia y modelos hidrologicos.

- Separar carpetas:
  app/services/report
  app/services/spatial
  app/services/export
  app/services/ia

Conclusion:
La arquitectura ya no queda amarrada a React para el PDF final. React puede seguir como visor GIS, dashboard y chat, mientras Typst queda como renderer final profesional.
